# 파피티 언어 모델 v0.6

v0.6은 작은 무작위 초기화 Transformer의 학습·평가 실험이다. 문법 교정기나
범용 수학 추론 모델의 완성을 의미하지 않는다. 기존 Native/Hybrid 및
v0.1~v0.5 명령·가중치 형식은 보존한다. 기본 실행 모드는 바꾸지 않는다.

## 답변 하드코딩 금지

`python -m papiti_lm.v0_6 chat`은 체크포인트와 토크나이저를 읽고
`model.generate`의 자기회귀 예측을 그대로 출력한다. 계산기, 정답 사전,
검색, 외부 모델, 문장별 대체 답변을 사용하지 않는다. 틀린 예측도 바꾸지 않는다.
`serve`에서도 체크포인트 버전이 v0.6이면 `PAPITI_LM_ARITHMETIC=1`을
설정해도 기존 v0.4 계산기를 호출하지 않는다. 빈 출력은 API 오류로 처리한다.
API는 기존과 같이 마지막 사용자 메시지만 사용한다. 대화 이력 전체를
이해하는 모델로 소개하지 않는다. 상황 학습의 앞뒤 문맥은 한 입력 안에 포함한다.

## 학습 자료와 출처

`training/papiti_v0_6_curriculum.json`에 새로 쓴 한국어 상황 30개 묶음과
수학 개념 50개 묶음을 기록했다. 문항별 `source`는 같은 파일의 원출처 URL과
자료 설명을 가리킨다. 개인 대화나 비공개 문서를 자동 수집하지 않는다.
수식과 짧은 한국어 설명은 새로 작성한 수학적 사실 요약이며 원문 복사가 아니다.
원자료를 재배포할 때는 각 출처의 이용 조건을 별도로 확인해야 한다.

- 상황: 인사/감사, 승리/패배, 부정·정정, 생략된 대상 확인, 단위 확인,
  주어·목적어·서술어 순서, 호응, 공손한 요청, 한 문장 설명, 지시 대상 찾기.
- [OpenStax 미적분](https://openstax.org/details/books/calculus-volume-1):
  미분·적분, 테일러 전개, 급수 수렴, 벡터 미적분과 경계 정리.
- [MIT 18.06](https://ocw.mit.edu/courses/18-06-linear-algebra-spring-2010/):
  고유값, SVD, 스펙트럼 정리, 계수·영공간, 최소제곱, 대각화, 정사영.
- [MIT 18.440](https://ocw.mit.edu/courses/18-440-probability-and-random-variables-spring-2014/):
  베이즈 정리, 모멘트, 중심극한정리, 확률 부등식과 조건부 분산.
- [NIST DLMF](https://dlmf.nist.gov/): 감마·베타함수, 반사공식,
  스털링 근사, 베셀·에어리·초기하함수, 타원적분, 제타함수,
  팽르베 I·II 비선형 방정식, 푸리에·라플라스 변환.

수식의 정의역, 비영 조건, 수렴 조건, 경계 방향, 변환 관례를 설명에 포함했다.
모든 수학이나 가장 어려운 모든 공식을 담았다는 주장은 하지 않는다.
일부 개념 전체를 시험으로 남겼으므로 50개 모두가 훈련에 들어가는 것도 아니다.
실제 훈련 개념은 36개(질문 표현 72개), 검증은 6개, 최종 시험은 8개다.

## 누수 방지와 훈련

기존 721문항은 같은 질문의 공백·문장부호·대소문자·Unicode 차이를 제거한 뒤,
질문을 공유하는 원래 그룹을 연결 요소로 합쳐 세 갈래로 나눈다. 원래 같은
출처 그룹도 분리하지 않는다. 새 교육 자료와 겹치는 기존 질문은 제외한다.
훈련/검증/시험 사이에 정규화 질문이나 가족 ID가 겹치면 실행을 중단한다.
덧셈은 교환 순서까지 같은 피연산자 묶음을 함께 배정하며 `1+1` 등 기존
실패 사례 8개는 최종 시험에만 남긴다. 학습 전 정답 계산은 오직 지도학습
레이블을 만드는 데 사용한다. 추론 경로에서는 사용하지 않는다.

seed 42 기본 설정의 문항 수:

| 영역 | 훈련 | 검증 | 최종 시험 |
| --- | ---: | ---: | ---: |
| 한국어(기존+신규) | 489 | 132 | 146 |
| 덧셈 | 1200 | 80 | 88 |
| 수학 개념 질문 | 72 | 6 | 8 |

토크나이저는 훈련 문항 및 훈련 문장부호 변형에만 적합한다.
문장부호 변형도 시험 질문과 겹치면 제외한다. 훈련 자료에 없는 글자는 UNK로
인코딩되며 평가에는 정답의 UNK 비율을 함께 기록한다.

각 epoch의 표본 비중은 한국어 50%, 덧셈 25%, 지식 25%다.
한국어 문항은 매번 모두 사용하고 다른 영역은 그에 맞게 표본을 구성한다.
긴 수학 답변 때문에 토큰 비중까지 같지는 않다. 1~2 epoch는 기초,
3~4는 중급, 5 이후는 고급까지 사용한다. 모든 지식은 처음부터 훈련용
토크나이저에 포함하지만 고급 문항의 최적화는 5 epoch부터 시작한다.

정답 토큰의 교차엔트로피 외에 훈련용 인사/감사 및 승리/패배 대조 쌍의
응답 likelihood 순위 손실을 4 batch마다 더한다. 반대 상황의 답변보다
적절한 답변에 높은 확률을 주도록 학습한다. 이는 훈련 손실이고 추론 규칙이 아니다.
기울기 clipping, AdamW, 고정 seed를 사용한다. 전체 커리큘럼에 진입한
5 epoch부터 검증 문자 NLL의 가중합(한국어 .6, 덧셈 .2, 지식 .2)으로
체크포인트를 선택한다. 최종 시험 점수로 epoch나 하이퍼파라미터를 고르지 않는다.
1 epoch의 같은 초기화·자료 모델도 저장해 학습량 대조군으로 평가한다.
v0.5와는 분리 방식과 자료가 달라 절대 NLL을 직접 우열 비교하지 않는다.

## 실행

CPU PyTorch와 기존 FastAPI/uvicorn 의존성이 설치된 환경에서 실행한다.

```bash
make papiti-lm-train-v0.6
make papiti-lm-eval-v0.6
make papiti-lm-chat-v0.6
make papiti-lm-serve-v0.6
python -m unittest tests.test_papiti_lm tests.test_papiti_v0_6 -v
```

Windows 등 `make`가 없는 환경의 직접 실행:

```bash
python -m papiti_lm.v0_6 train --epochs 12 --baseline-checkpoint artifacts/papiti_language_v0_6_epoch1.pt
python -m papiti_lm.v0_6 eval --compare-checkpoint artifacts/papiti_language_v0_6_epoch1.pt --report reports/papiti_v0_6.json
python -m papiti_lm.v0_6 chat --message "1+1은?"
python -m papiti_lm.v0_6 serve --port 8765
```

학습 JSON과 기존 데이터 및 데이터 생성 코드의 SHA-256을 체크포인트에 기록한다.
평가 시 일치하지 않으면 중단한다. 12 epoch 소형 모델의 실험이며 실제
파라미터 수는 실행 로그를 기준으로 한다.

## 최종 시험과 문장 적절성 검토

전체 최종 시험의 영역별 토큰·문자 NLL과 문자 perplexity를 기록한다.
새 상황 질문 10개, 덧셈 88개 전체, 완전히 미학습인 수학 개념 8개 전체를
temperature 0, 최대 128 토큰으로 생성해 정답과 나란히 JSON에 저장한다.
수학은 공백과 Unicode 표기만 정규화한 exact match이므로 동치인 다른 수식이나
올바른 설명도 실패로 잡힐 수 있다. 이는 증명·추론 능력 시험을 대신하지 않는다.
시험용 역전승/역전패 대조 쌍에는 적절한 답과 반대 상황 답의 NLL도 비교한다.

반복 삼중어절, 빈 출력, 깨진 Unicode, 종결 문장부호 수, 상황 핵심어와
부적절한 핵심어를 진단한다. 핵심어 포함만으로 올바른 문장이라고 판정하지 않는다.
각 생성 문항의 `human_scores_0_to_2`는 다음 기준으로 사람이 채운다:

| 항목 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 문법·어순 | 해석 곤란 | 일부 어색함 | 자연스러운 완결문 |
| 상황·의도 | 반대 상황/요구 무시 | 부분 반영 | 맥락과 요청을 정확히 반영 |
| 일관성·반복 | 의미 붕괴/반복 | 경미한 반복 | 일관되고 중복 없음 |
| 사실·수학 | 오답 | 부분 정답/조건 누락 | 정답 및 필요한 조건 충족 |

문법·상황·일관성에서 모두 2이고 사실 오답이 없어야 개별 응답을 적절하다고
볼 수 있다. 자동 시험은 이를 보증하지 않는다. 생성 JSON의 모든 답변을
확인해야 하며, 자동으로 사람 점수를 채우지 않는다. 체크포인트의 일반화나
사용자 체감 품질 개선은 별도 검토가 끝나기 전에는 주장하지 않는다.

## GitHub Actions와 결과의 의미

`Papiti v0.6 curriculum and unseen evaluation`이 기존 버전 테스트,
누수·역전파·추론 우회 방지 테스트, 12 epoch 훈련, 대조군 및 최종 시험,
가중치와 전체 생성 기록 업로드까지 실행한다. artifact 이름은
`papiti-v0-6-model-only-evidence`, 보관 기간은 14일이다.
일반 tests workflow는 Native/Hybrid 회귀 및 프런트엔드도 확인한다.
기존 버전 학습 workflow도 변경 없이 계속 실행된다.

Actions 성공은 코드와 학습·평가 파이프라인이 정상 실행됐다는 뜻이다.
수학 정답률이나 대화 품질이 높다는 의미는 아니다. JSON의 `release_ready`는
자동으로 true가 되지 않는다. 이 실험을 병합해도 기본 앱이나 모델을
v0.6으로 자동 전환하지 않는다.

## 실제 실행 결과: 2026-11-11, 한국 시간

[PR #79](https://github.com/codingguy1026/FlyGPT/pull/79)의 코드 커밋
`eeda0ed18d3f2e30379f978014a554999460a041`에서 실행했다.
[v0.6 학습·평가 실행](https://github.com/codingguy1026/FlyGPT/actions/runs/43034627609)은
성공했고, 같은 커밋의 일반 tests 및 기존 언어 모델 workflow 6개도 모두 성공했다.
일반 테스트는 339개 중 선택적 의존성 관련 24개를 건너뛰고 통과했으며,
CPU PyTorch가 있는 v0.6 workflow에서는 모델 테스트 31개를 모두 통과했다.
프런트엔드 타입 검사와 빌드도 통과했다. 로컬 Windows 전체 회귀에서는
기존 SQLite 파일 잠금으로 20개 정리 오류가 발생했지만 Linux CI에는 재현되지 않았다.

모델은 686,592 파라미터, 어휘 940개, seed 42, 12 epoch 설정이다.
전체 커리큘럼을 사용한 epoch 중 검증 점수가 가장 낮은 **epoch 5**가 선택됐다.
1 epoch 대조군과 같은 미학습 최종 시험에서 얻은 수치는 다음과 같다.
문자 NLL은 낮을수록 좋지만 자연스러운 문장이나 정답을 보장하지 않는다.

| 최종 시험 | 1 epoch 문자 NLL | 선택 모델 문자 NLL | 선택 모델 생성 결과 |
| --- | ---: | ---: | --- |
| 한국어 146문항 | 3.17390 | 3.07284 | 새 상황 10개 핵심어 진단 0/10 |
| 덧셈 88문항 | 2.30752 | 1.49360 | exact match 1/88, 약 1.14% |
| 미학습 수학 개념 8문항 | 4.31650 | 4.50092 | exact match 0/8 |

수학 개념 시험의 NLL은 오히려 나빠졌다. 한국어/덧셈 NLL 감소만으로
전체 품질 향상을 주장할 수 없다. 역전승/역전패 답변 likelihood 대조는 1/2이며
실제 생성 응답의 적절성과 별개다. 정답의 미지 토큰 비율은 한국어 1.16%,
지식 1.53%, 덧셈 0%였다.

다음은 대체하지 않은 실제 모델 출력이다.

| 입력 | 출력 |
| --- | --- |
| `1+1은?` | `1` (오답, 정답 2) |
| `23+47은?` | `91` (오답, 정답 70) |
| `41+60은?` | `101` (88개 중 유일한 정답) |
| 오류 해결 후 감사 표현 | `어떤 줘.` |
| 농구 역전승 소식 | `가장 테일작여을 보자.` |
| 농구 역전패 소식 | `어떤 이야기를 있어?` |
| 응결을 한 문장으로 설명 요청 | `어떤 있어?` |

새 상황 10개 전체를 Codex가 문법·의도·일관성 기준으로 출력별 검토했다.
자연스럽고 요청에 적절한 응답은 **0/10**이었다. 이는 사람이 독립적으로
매긴 점수가 아니며, 원본 JSON의 사람 평가 항목은 비워 두었다.

| 상황/요청 | 출력별 부적절성 |
| --- | --- |
| 오랜만의 인사 | 인사 대신 무관한 수식 조각 생성 |
| 감사 | 불완전한 `어떤 줘.` 생성 |
| 역전승 | 축하 없이 어휘·어순 붕괴 |
| 역전패 | 감정 반영 없이 호응이 깨진 질문 생성 |
| 불합격으로 정정 | 정정을 반영하지 않고 미분 조각 생성 |
| 문장 어순 교정 | 원래 인물·목적어를 보존하지 못함 |
| 교수님께 정중한 요청 | 공손한 요청을 구성하지 못하고 의미 붕괴 |
| 생략된 대상 확인 | 필요한 확인 질문을 만들지 못함 |
| 한 문장 개념 설명 | 개념을 설명하지 못함 |
| 지시 대상 확인 | 제공된 인물을 답하지 못함 |

일부 출력에는 같은 단어나 수식 조각이 반복됐지만 정확히 같은 삼중어절이
반복되지는 않아 자동 반복 지표는 0이었다. 이 지표가 0이어도 문장이 좋다는
뜻이 아니라는 실제 반례다. 훈련 손실 감소와 검증 손실 상승은 과적합 경향도
보였다. 단계별·대조 학습과 지식 추가 자체의 효과를 분리하는 ablation,
여러 seed, 더 큰 원본 상황 자료에 대한 실험은 아직 수행하지 않았다.
