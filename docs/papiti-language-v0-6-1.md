# Papiti v0.6.1 Hybrid language speaker

This is a separate, research-only conditional speaker for the existing
MaleCNS + Python reasoning design. It does not replace the brain/router,
solve mathematical problems, or create new facts.

## Architecture

User message -> MaleCNS router -> Python brain / evidence plan
-> completed mouth_only_v1 semantic packet -> trained v0.6.1 Transformer
-> strict semantic-preservation checks -> user response.

- The upstream brain still selects the act, content units, style,
  verified facts, and exact tool results.
- The neural mouth sees only the completed semantic packet and learns
  how to express it. It does not receive a question-to-answer lookup table.
- papiti_lm.v0_6_1 infer does not import arithmetic or training labels.
  All final neural strings are generated by the scratch Transformer.
- Bad or unsafe outputs, missing weights or invalid evidence never become
  Native-generated Hybrid answers. If an explicitly configured local model
  cannot safely generate an answer, the app reports a generation failure.
- Unresolved free-form tasks are not silently sent to the speech-only
  network. The upstream Python engine must supply actual meaning first.

## Reproduce locally / Codespaces

    git pull origin main
    make train-setup
    make papiti-lm-train-v0.6.1
    make papiti-lm-eval-v0.6.1
    make hybrid

Or use the GitHub Actions training artifact and extract its .pt file to
artifacts/papiti_language_v0_6_1.pt before make hybrid. There is no
automatic model download or implicit training on app startup.

The train-setup command creates a CPU PyTorch .venv-train used by
training and subprocess inference. If PyTorch is in another virtualenv,
set FLYGPT_HYBRID_SPEECH_PYTHON to its Python executable. To choose
another checkpoint set FLYGPT_HYBRID_SPEECH_CHECKPOINT.

make hybrid requests FLYGPT_HYBRID_SPEAKER=v0.6.1 by default.
The presence of a checkpoint is visible in GeneratorRuntime.status() under
hybrid_speaker_checkpoint_present. That flag alone does not prove
the neural speaker has good grammar or correct answers. The provider of each successful answer reports the actual language model.
Failures are explicit, not disguised as a deterministic reply.

Disable the new speaker without changing Native or historical HTTP Hybrid:

    FLYGPT_HYBRID_SPEAKER=legacy make hybrid

## Neural-only Hybrid policy

The Hybrid conversation generator now requires real language-model output.
For a completed semantic packet, it tries the local v0.6.1 speaker first.
A separately configured local endpoint (FLYGPT_HYBRID_URL and
FLYGPT_HYBRID_MODEL) can handle authorized open-ended tasks and can serve as
a second language model when v0.6.1 is rejected or missing. No external
provider is selected implicitly.

If neither neural path can produce a validated answer, the request reports
a language-model-unavailable error, not a Native substitute. This does NOT
make the small v0.6.1 model an open-domain reasoner. Verified tool result
routes such as math and neuron lookups remain independent of conversational
language generation.

## What was trained and what was not

A small Transformer is trained from random initialization on the
existing Python brain's ready speech plans, project fact packets, and
numeric semantic packets. Supervised training references are created
offline, never used as runtime answers.

Split boundaries exclude exact semantic packets across train, validation,
and test. The unseen numeric values measure whether the model copies a
supplied verified result, NOT whether it can calculate addition.

Known limitations: This training corpus is very small and cannot
establish good open-domain Korean. Strict fact checks may reject many
generated outputs. This is intentional: it protects verified upstream
meaning and makes fallback behavior honest. The local subprocess adds
startup and inference latency. No model is silently marked production
ready merely because CI succeeds.

## First measured experiment, 2026-11-12

GitHub Actions run #43052648076 trained a 381,504-parameter random-initialized
v0.6.1 speaker from 304 offline supervised rows. The best checkpoint
was selected after epoch 11 using validation loss.

- Unseen packet exact-match: 21/22 (95.5%). IMPORTANT: 20 of these
  packets supply a number to copy; this is not arithmetic generalization
  or broad Korean quality.
- A true Hybrid runtime integration (not mocks) generated and accepted:
  - Korean greeting: "안녕" -> "안녕! 반가워."
  - Thanks: "고마워" -> "천만에!"
  - Farewell: "잘 가" -> "잘 가!"
  - Identity: "너 누구야?" -> the 3 complete project facts supplied upstream.
- All four were tagged papiti-hybrid-v0.6.1, with finish reason
  neural_semantic_realization. None came from Native fallback.
- This proves the wiring and limited semantic-to-speech ability only.
  No claim of free-form reasoning, reliable open-domain Korean or
  production readiness. Human review and broader semantic evaluation
  are still required.
